# AgentGuard

> **AI로 작업하는 팀원은 [`AGENTS.md`](AGENTS.md)를 먼저 읽으세요.** 규칙·구조·문서 라우팅이 한 곳에 있습니다.

**선언한 기능:** AgentGuard는 사용자가 위임한 구매 예산·판매자·상품·기한을 코드로 강제하고, 범위 밖 지출을 차단하며, 승인과 거래 근거를 남기는 지출 통제 도구입니다.

AI 에이전트의 지출 요청을 사용자 정책으로 검증하고, 허용 범위를 벗어난 결제를 차단하며, 승인부터 온체인 결과까지 감사 가능한 기록으로 남기는 GWDC 2026 해커톤 프로젝트입니다.

## 현재 단계

자연어 정책 작성부터 거래 판정, 사용자 승인·거절, 해시 체인 감사 기록까지 이어지는 작동형 MVP입니다. Kiln API가 설정되면 `Qwen3-32B`로 정책 초안을 만들고, 연결되지 않았거나 응답이 실패하면 안전 규칙 변환기가 같은 흐름을 유지합니다. 실제 결제는 시뮬레이션입니다. 감사 해시를 Ethereum Sepolia에 기록하는 경로는 구현됐으며 실제 테스트넷 거래는 아직 실행하지 않았습니다.

### 구현된 핵심 흐름

1. 자연어 지출 조건을 상품·판매자 카탈로그에 대조해 구조화된 정책 초안으로 변환
2. 문장에 없는 자동 승인 한도·기한은 추측하지 않고 사용자에게 확인 질문
3. 사용자가 확인 필요 항목을 채운 뒤에만 정책을 최종 적용
4. 코드 기반 정책 엔진이 자동 승인·승인 대기·차단 판정
5. 사람이 대기 요청을 승인하거나 거절
6. 모든 이벤트를 SHA-256 해시 체인으로 연결해 변조 여부 검사
7. 정책과 감사 상태를 로컬 JSON에 저장해 서버 재시작 후에도 유지
8. 단계 완료 후 다음 화면으로 자동 이동하고 승인·거절 결과를 부드러운 전환으로 안내
9. Kiln 응답의 입력·출력·합계 토큰 수를 정책 해석 흐름별로 영구 저장하고 감사 화면에 표시
10. 정책별 누적 지출과 승인 대기 예약액을 합쳐 총예산을 검사하고, 사용자가 위임을 중지하면 이후 요청을 차단
11. 요청 당시 정책 스냅샷과 판정 로그를 묶은 구매 판단 영수증 조회
12. 브라우저 지갑으로 감사 해시를 Sepolia에 기록하고 서버가 거래 데이터·영수증을 확인한 뒤 앱 영수증에 연결

## 2026-09-27 보완 사항과 연결 준비

- 최대 예산과 승인 기준을 문맥으로 분리합니다. 승인 기준이 예산보다 크면 예산을 늘리지 않고 사용자 확인을 요구합니다.
- 정책 해석 원문·초안·AI 후보와 사용자가 수정한 최종 값을 감사 로그에 기록합니다. 요청 검사시간, 승인 처리시간과 대기시간도 기록합니다.
- 승인 직전에 현재 정책·기한·예약액을 다시 검사합니다. 같은 요청 ID 재시도는 중복 차감하지 않으며, 같은 ID로 내용을 바꾸면 409로 거부합니다.
- 디자인은 제공된 bleibtgleich HAR의 8열 그리드·큰 글자·얇은 선·완만한 모션을 참고했습니다. 사이트의 폰트·이미지·스크립트는 복사하지 않았습니다. 동작 줄이기 설정을 따릅니다.

운영자 로그인은 `.env`의 `OPERATOR_PASSWORD`와 `OPERATOR_ID`로 설정합니다. 비워 두면 화면에 **로컬 데모**로 표시됩니다. 설정한 경우 HttpOnly 세션 쿠키로 운영자 API를 보호합니다. 이는 단일 운영자 MVP이며 다중 사용자 RBAC는 구현하지 않았습니다. 서버는 localhost에 바인딩합니다. 공개 운영에는 HTTPS와 별도의 운영 보안 검증이 필요합니다.

외부 에이전트 연결은 서버의 `AGENT_API_TOKEN`, `AGENT_ID`를 설정합니다. 토큰이 없으면 에이전트 경로는 503입니다. 토큰은 요청 검사만 허용하고 정책 적용·사용자 승인을 허용하지 않습니다.

1. `GET /api/agent/policy`에서 `{policy}`를 받습니다.
2. `POST /api/agent/requests`에 `{productId, fee, policyId, clientRequestId}`를 보냅니다. 헤더는 `Authorization: Bearer <token>`입니다.
3. 재시도는 같은 정책·본문·요청 ID를 유지합니다. 응답의 allow / needs_approval / block은 정책 판정이며 실제 결제 완료가 아닙니다.

예제 실행(토큰은 `.env`에만 설정):

```bash
node --env-file=.env scripts/agent-request.mjs keyboard-safe
```

재시도할 때 예제가 출력한 ID를 `AGENT_REQUEST_ID` 환경변수로 지정합니다. 검사는 데모 장부에 반영되므로 실제 사용자 데이터 대신 `AGENTGUARD_STATE_FILE`로 별도 파일을 지정한 서버에서 시연하세요.

정책 API는 이제 해석 응답의 `interpretationId`와 함께 `POST /api/policies`에 `{draft, interpretationId}`를 전달합니다. 원문·provider를 위조한 적용 요청은 거부합니다.

**미검증:** 행사 Kiln 키를 아직 받지 못했으므로 실제 Qwen3-32B 호출, 실제 에이전트의 자율 구매와 결제, Sepolia 거래는 완료로 표시하지 않습니다. HTTP 에이전트 계약은 테스트용 토큰과 격리 데이터로 검증했습니다. 기존 고정 상품 카탈로그는 데모용이며 다양한 실제 판매처 연결은 후속 범위입니다.

## 시작하기

```bash
cp .env.example .env
npm install
npm run dev
```

- 웹: <http://localhost:5173>
- 서버 상태 확인: <http://localhost:8787/api/health>

Kiln 연동 없이도 로컬 데모가 작동합니다. 제공받은 OpenAI 호환 Kiln API가 있다면 `.env`의 `KILN_API_URL`, `KILN_API_KEY`를 설정하고 `KILN_MODEL=qwen3-32b`(Kiln 문서 기준 ID)를 사용합니다. 연결 점검은 `node --env-file=.env scripts/check-kiln.mjs`로 합니다. `GET /api/ai/usage`에서 실제 응답의 토큰 사용량을 확인할 수 있습니다. 비밀키는 절대 커밋하지 않습니다.

게이밍 모니터 문장을 입력한 뒤 **정책 초안 만들기**를 눌러 새 해석 결과를 확인합니다. 입력을 바꾸면 이전 초안을 지우고 진행 중인 해석 요청을 취소합니다. Kiln이 문장에 명시된 상품 종류와 다른 카테고리를 제시하더라도 카탈로그와 코드의 명시적 추출 결과가 우선합니다. 규칙으로 식별하지 못한 상품은 Kiln이 카탈로그 후보를 채울 수 있지만 사용자가 확인해야 적용됩니다.

총예산은 정책 버전별 누적 한도입니다. 새 정책을 적용하면 새 위임과 예산이 시작되고 이전 감사 기록은 보존됩니다. 데모는 승인 대기 요청을 먼저 만든 뒤 거절해 예약액을 해제하고, 정상 구매와 미등록 판매자 요청을 차례로 실행하면 됩니다.

공식 Challenge B의 실제 Kiln 호출과 테스트넷 거래는 자격 증명을 받은 뒤 현장에서 검증해야 합니다. 현재 로컬 폴백이나 모의 거래를 해당 증거로 제시하면 안 됩니다.

테스트넷 기록에는 Sepolia RPC를 `.env`의 `RPC_URL`에 넣고 `CHAIN_ID=11155111`을 유지합니다. 브라우저의 EVM 지갑을 Sepolia로 전환하고 테스트넷 ETH를 준비한 뒤, 감사 화면의 **지갑으로 해시 기록**을 누릅니다. 지갑이 소각 주소(`0x…dEaD`)로 보내는 0 ETH 거래의 데이터에 감사 해시를 담습니다. 거래가 확정되면 **확정 거래 검증**을 눌러 RPC가 반환한 거래·영수증과 앱 해시를 대조합니다. 개인키는 서버나 앱에 입력하지 않습니다.
