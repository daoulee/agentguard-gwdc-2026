# Challenge B 제출 준비

공식 문서: [FuriosaAI × Bricksum Challenge Brief](https://docs.google.com/document/d/13qh7oePGl7Flrl-Zh_A6hfr02L266PvS/edit)

## 선언한 기능과 경계

AgentGuard는 사용자가 위임한 구매 예산·판매자·상품·기한을 코드로 강제하고, 범위 밖 지출을 차단하며, 승인과 거래 근거를 남기는 지출 통제 도구입니다. 대상은 AI 에이전트에게 구매를 맡기되 사후에 허가 범위를 확인해야 하는 사용자입니다. LLM은 자연어를 정책 초안으로 바꾸고, 결제 허용 여부는 `packages/policy/src/index.ts`의 결정론적 엔진이 판단합니다.

| 공식 조건 | 현재 상태 | 제출 전 증거 |
|---|---|---|
| 범위 밖 요청 2건 차단 | 예산+수수료 초과, 미등록 판매자 차단 구현 | 두 요청의 감사 로그와 정책 버전 보존 |
| 실제 Kiln `Qwen3-32B` 호출 | 연결 코드와 모델명 설정, 응답 토큰 기록 구현 | 현장 API 호출 성공 화면, 모델명, 입력·출력 토큰 기록 |
| 흐름별 토큰·에너지 설명 | 정책 해석 흐름별 사용량 API·화면 구현 | 측정값 수집 후 추론당 에너지 측정값 또는 가정과 계산식 제시 |
| 테스트넷 온체인 거래 | Sepolia 지갑 제출과 RPC 검증 경로 구현, 실제 거래 미실행 | 거래 해시, 체인 탐색기 URL, 대응 감사 이벤트 |
| 사람의 예산 부여·관찰·중지·영수증 | 누적 예산, 위임 중지, 정책 스냅샷 영수증 구현 | 실제 테스트넷 거래 영수증 연결 |
| 제3자 기록 재구성 | SHA-256 해시 체인과 요청 당시 정책 스냅샷 구현 | 온체인 거래 해시를 대응 기록에 연결 |

## API와 측정

1. 행사에서 받은 Kiln URL과 키를 `.env`에 입력한다. 모델은 반드시 `Qwen3-32B`로 유지한다.
2. 정책 해석을 한 번 실행하고 `GET /api/ai/usage`에서 `status=success`, `provider=kiln`, `model=Qwen3-32B`를 확인한다. `promptTokens`, `completionTokens`, `totalTokens`는 공급자 응답에 값이 있을 때만 기록된다. 값이 없으면 측정 안 됨으로 남긴다.
3. 거래 평가·승인·차단은 LLM을 재호출하지 않는다. 발표 시 이 구분을 불필요한 추론 절감 근거로 설명한다.
4. 에너지 추정은 실측 자료가 있을 때 `추론 에너지 = 요청별 NPU 평균 전력(W) × 추론 시간(s) / 3600` Wh로 계산한다. 전력과 시간을 측정하지 못하면 수치를 만들어내지 않고 가정값과 출처를 별도 표시한다.

## 테스트넷 감사 해시

1. Sepolia RPC URL을 `RPC_URL`에 설정하고 `CHAIN_ID=11155111`을 유지한다. 브라우저 지갑은 Sepolia 테스트넷을 선택한다.
2. 구매 요청과 승인·차단 기록을 만든 뒤 감사 화면에서 최신 감사 해시를 지갑 거래 데이터로 제출한다. 거래는 자기 주소로 보내는 0 ETH 거래이며 테스트넷 가스가 필요하다.
3. 확정 후 검증 버튼을 누른다. 서버는 `eth_chainId`, `eth_getTransactionByHash`, `eth_getTransactionReceipt`를 조회해 체인 ID, 거래 데이터, 발신·수신 주소, 금액 0, 성공 상태를 확인한다.
4. 영수증에서 거래 해시와 기록 해시를 나란히 확인한다. 실제 해시가 생기기 전까지 온체인 증거를 제출한 것으로 표시하지 않는다.

참고: [Ethereum JSON-RPC](https://ethereum.org/developers/docs/apis/json-rpc/), [EIP-1193 지갑 인터페이스](https://eips.ethereum.org/EIPS/eip-1193)

## 3분 발표 흐름

1. **0:00–0:30 문제:** AI가 돈을 쓸 때 결제 기록만으로는 사용자가 무엇을 허용했는지 알 수 없다.
2. **0:30–1:00 정책:** 한국어로 예산·상품·판매자·기한을 말한다. Kiln이 초안을 만들고 누락 조건은 사용자에게 묻는다.
3. **1:00–1:40 경계:** 승인 대기 1건을 거절해 예약액을 해제한 뒤 정상 구매, 수수료 포함 예산 초과, 미등록 판매자 요청을 실행한다. 누적 예산과 차단 근거를 로그에서 확인한다.
4. **1:40–2:20 사람과 체인:** 승인 대기 건을 사람이 처리한다. 테스트넷 해시와 앱 기록을 나란히 보여준다.
5. **2:20–3:00 효율·검증:** 실제 정책 해석 토큰 수와 결정론적 판정의 무추론 구조를 설명하고, 제3자가 정책·승인·거래 기록을 재구성한다.

리허설 실패 시 폴백은 제품 흐름 확인에만 사용한다. 실제 Kiln 호출 및 온체인 거래가 빠졌다면 제출 조건을 충족했다고 주장하지 않는다.
