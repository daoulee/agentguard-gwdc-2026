## 결론

현재 웹은 **TRON 자산 배분·수익 계획**이라는 주제와 사용자 입력 → 두 계획 비교라는 첫 흐름에 맞는다. 다만 공식 Challenge B가 요구하는 **AI 기반 요구 파악, 검증 가능한 생태계 데이터, 실행, 포지션 관리·리뷰**는 아직 구현되지 않았다. 따라서 제출 시점에 이 웹을 완성된 AI 투자 도우미라고 소개하면 실제 동작과 어긋난다. 지금은 화면 시연용 프로토타입으로 설명하는 것이 정확하다.

이 평가는 [GWDC TRON Challenge Brief 2쪽](https://drive.google.com/file/d/1HXLhu1_vCoMD5aN3APEYEjDrh9oVCj7g/view)의 Acceptance Criteria와 현재 `frontend/src/App.tsx`, `frontend/README.md`, `contracts/README.md`를 대조한 것이다.

## 우선순위와 구현 제안

### P0 — 데모의 신뢰성과 과제 적합성

1. **실제 데이터 연결.** JustLend·USDD의 구체적인 상품/전략을 먼저 확정한다. 각 값에 프로젝트명, 상품명, 체인, 원본 URL/API, 조회 시각, 적용 조건을 붙인다. 데이터가 실패하거나 오래되면 추천을 중지하거나 명확히 오래된 값으로 표시한다. 현재 `DEMO_RATES`와 `1.6 USDD` 비용은 실거래 근거가 없으므로 실제 추정치처럼 보이지 않게 한다.
2. **실행 가능한 두 계획.** 각 계획의 배분액, 기본 수익, 기간 제한이 있는 인센티브, 예상 온체인 비용, 입금 조건, 회수 가능 시점, 주요 위험을 같은 기준으로 보여준다. 비교 대상이 진짜로 참여 가능한지, 보유 자산에서 필요한 토큰으로 이동하는 과정이 무엇인지 확인한다.
3. **AI 역할을 명확히 구현.** 대화로 부족한 조건을 묻고, 추천의 이유를 입력 조건과 상품 근거에 연결한다. AI가 생성한 설명과 실제 계산은 분리하고, 계산값·출처는 검증 가능한 코드가 제공한다. 답변이 모르는 조건이나 오래된 데이터를 확신해서 말하지 않도록 한다.
4. **시연 시나리오를 한 번 끝까지 연결.** 요구 분석 → 조건 확인 → 두 계획 비교 → 사용자 선택 → 행동 미리보기 → 명시적 승인 → 실행 결과 또는 명시된 시뮬레이션 → 예상/결과 리뷰를 한 세션에서 보여준다. 공식 기준에 실행이 포함되므로 시뮬레이션만 구현했다면 실행 기준은 여전히 부분 충족이라고 설명한다.

### P1 — 실제 사용과 심사 질문 대비

5. **승인·거래 안전장치.** 예치/회수 전에 금액, 대상 계약, 예상 수수료, 승인 범위, 실패 가능성을 표시한다. 지갑 연결과 거래는 사용자가 명시적으로 확인할 때만 시작한다. 무제한 토큰 승인 대신 필요한 범위를 우선 검토하고, 테스트넷/메인넷을 분명히 구분한다.
6. **기록과 재평가.** 원래 계획, 데이터 시각, 수익률 가정, 선택 이유를 저장한다. 이후 수익률·유동성 조건이 달라질 때 재배분안을 제안하고, 예상 대비 결과와 거래 해시 또는 시뮬레이션 표시를 남긴다.
7. **오류·경계 사례.** 잔고 부족, 입력값 오류, 데이터 조회 실패, 지갑 거부, 거래 지연/실패, 인센티브 종료, 조기 회수 제한을 시연한다. 모바일에서도 같은 확인 정보를 볼 수 있어야 한다.

## 현재 코드에서 바로 고칠 부분

- `frontend/src/App.tsx`의 `createPlans()`는 유동성·위험 선택에 따른 고정 비율 규칙이다. AI 추천으로 소개하지 말고, 실제 AI 판단과 검증 가능한 계획 계산을 추가한다.
- `DEMO_RATES`와 `estimates()`의 비용 `1.6`은 가정값이다. 실제 데이터가 연결되기 전에는 화면과 발표 모두에서 시연값이라고 명확히 표시한다.
- `USDD 수익 전략`은 구체적 상품/계약과 참여 조건이 없는 이름이다. 실제 USDD 기회를 특정하고, JustLend와 별개 프로젝트 데이터를 어떻게 사용했는지 보여준다.
- `localStorage`에는 선택한 계획 초안만 남는다. 원본 데이터 시각, 계산 가정, 계획 버전, 실행/리뷰 기록은 저장되지 않는다.
- `contracts/contracts/AgentGuardVault.sol`은 **AI 지출 통제 금고**로, 자산 배분·수익 계획의 예치/회수 계약이 아니다. TRON B 데모의 핵심 기능으로 연결했다고 주장하지 않는다.

**첫 단계:** 상품·데이터 소스와 실행 가능한 두 계획을 확정한다. **다음 단계:** 대화형 요구 분석과 근거 설명을 붙인다. **마지막 단계:** 확인→실행/명시된 시뮬레이션→기록·리뷰를 연결하고 전체 시나리오를 반복 검증한다. UI 장식보다 이 흐름의 정확성이 현재 더 중요하다.
